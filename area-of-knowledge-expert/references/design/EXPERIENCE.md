# Knowledge Map — Experience Spine

## Foundation

This spine describes a single static HTML page, one per area of knowledge, generated by **Agent E (Visual Map Generator)** of the `area-of-knowledge-expert` skill and opened in the default browser when the run finishes. It is for desktop browsers only and uses a dark theme only. It has no framework: plain HTML, CSS, inline SVG and vanilla JS, plus Google Fonts (Orbitron and Inter). The page assumes an internet connection; working offline is not required.

`DESIGN.md` is the visual identity reference. The working reference implementation is **`assets/knowledge-map-template.html`**. Agent E (`scripts/build_map.py`) copies it and writes **only** the JSON inside `<script type="application/json" id="km-data">` (see *Data Contract*); all other code is frozen. **This spine and `DESIGN.md` win on any conflict with the template or with `.working/` artifacts. `.working/` is exploration history and must not be used as a source.**

Stakes: a personal study tool. The audience is one person, the skill's author, getting oriented in a new field.

## Information Architecture

| Surface | Reached from | Purpose |
|---|---|---|
| **Map** (first viewport) | Page open · nav MAP · `footer` ↑ BACK TO MAP | See the whole area at once: the area in the center, its subfields around it, and how the subfields connect. Expand a subfield to see its topics. |
| **Overview** | Scroll · nav OVERVIEW · click the area name · click a subfield name on the map | A gentle introduction: an area intro (`00`), then one section per subfield (`01`–`06`). Each section has its text, a `topics-line` and a `connects-line`. |
| **Resources** | Scroll · nav RESOURCES · click a `citation-link` | Academic references in ABNT, grouped by subfield, each with a `type-tag` and an optional link. |

There is one page, scrolled vertically. The `top-bar` is fixed and always shows which section you're in. Navigation goes in one direction: the map jumps down into the text, and the text does not link back to specific map nodes. The nav, the footer and the browser's Back button return you to where you were.

## Voice and Tone

Microcopy is the terse voice of a control panel: uppercase Orbitron, middle dots as separators, no exclamation marks, no emoji. Reading text (Inter) is plain, warm and explanatory, like a good textbook intro. All content is in English.

| Do | Don't |
|---|---|
| `01 · 5 TOPICS · 9 SOURCES` | "This subfield has 5 topics and 9 sources!" |
| `CLICK DOT TO EXPAND · CLICK NAME TO READ · DRAG · CTRL+WHEEL TO ZOOM` | "Tip: try clicking on the nodes 🙂" |
| `SCROLL ↓ OVERVIEW + RESOURCES` | "Scroll down to learn more" |
| `TOPICS  AUTOMATA  COMPUTABILITY …` / `CONNECTS TO  02 ALGORITHMS & DATA STRUCTURES …` | "See also:" |
| `OPEN ↗` | "Click here to view the source" |
| `No sources found for this subfield.` | "Oops! Nothing here yet." |
| `NODES 07 · EDGES 07 · TOPICS 30 · SOURCES 48` | Telemetry that isn't true for this area |

## Component Patterns

These are behavioral rules. Visual specs are in `DESIGN.md.Components`, under the same names.

| Component | Behavioral rules |
|---|---|
| `node-root` | Fixed at the center. You can drag it, but it springs back on release. Its name is a real link to `#overview`. |
| `node-subfield` | It is a focusable button (`aria-expanded`). Clicking the dot without dragging, or pressing Enter or Space when focused, toggles its topics, and several can be open at once. Its **name** is a real link to `#sf-<id>`: pointer cursor, underline and blue on hover or focus. It navigates on click, so a press can be cancelled. Dragging moves the node and its topics; on release it springs back to its slot with a small overshoot. Focusing it highlights its neighbors, the same as hovering. |
| `node-topic` | Created when its subfield opens: it travels out from the subfield into its arc slot and fades in. It is not interactive. Its label hides at zoom ≤ 0.75×, unless its subfield or the topic itself is hovered. |
| `edge-spoke` / `edge-link` / `edge-topic` | Spokes join the center to each subfield. Links join subfields to each other and come from `connects` in DATA. Hovering or focusing a node turns its edges blue with a glow and fades every unconnected node and edge (`faded`). |
| `telemetry-ring` | Decorative and hidden from assistive technology. It rotates continuously and does not respond to input. |
| `telemetry-readout` | Shows the true counts computed from DATA (nodes, edges, topics, sources) and the live zoom level. |
| `map-hint` / `scroll-cue` | Static. The scroll cue is a link to `#overview`. |
| `top-bar` | MAP / OVERVIEW / RESOURCES scroll to their section. Scroll-spy marks the section in view as active. |
| `sticky-index-item` | Lists `00 INTRODUCTION` plus one item per subfield and stays pinned while you scroll through the Overview. Scroll-spy marks the section in view as active, and clicking an item scrolls to that section. |
| `section-heading` / `resource-group` | Static. Each section's anchor id is `sf-<id>`. |
| `topics-line` | Static list of the subfield's topics, so they are readable and searchable without the map. Left out when there are no topics. |
| `connects-line` | One link per connected subfield. Left out when the subfield has no connections. |
| `citation-link` | `(AUTHOR, YEAR)` in ABNT. On click it pushes `#ref-<id>` to history, scrolls the reference to the center, moves focus to it and flashes it blue for 1.6s. Back returns to the citation. |
| `resource-entry` | A list item that can receive focus (`tabindex=-1`). It shows the `type-tag`, the citation and, only when a URL exists, `OPEN ↗`, which opens in a new tab with an accessible "(new tab)" label. |
| `type-tag` | Static. |
| `footer` | Shows the generation stamp, plus ↑ BACK TO MAP. |

## State Patterns

| State | Treatment |
|---|---|
| **Initial load** | Waits for the web fonts, measures the widest topic label, then lays out the map. All subfields start **collapsed** and spread out. Nothing is selected and the nav shows no active item until the first scroll-spy callback. |
| **Fonts fail to load** | Falls back to `system-ui`; the layout still works. |
| **1–5 subfields** | The ellipse spaces N subfields evenly (360°/N, offset half a step). The index and resources show only those N. |
| **Subfield with fewer than 5 topics** | The arc stays centered on the outward direction. With 0 topics, the subfield has no `topics-line` and expanding it shows only the open ring. |
| **Long subfield name (> 18 chars)** | Wraps onto two balanced lines on the map. The index and headings keep the full name. |
| **Long topic labels / narrow window** | The ellipse shrinks (down to `{spacing.map-rx-min}`) so topic labels stay on screen. |
| **Subfield with no connections** | It keeps its spoke; its `connects-line` is omitted. |
| **Subfield with no resources** | The group still renders, with one muted row: `No sources found for this subfield.` Its meta line reads `0 SOURCES`. |
| **Resource without URL** | No `OPEN ↗`. |
| **Citation with no matching reference** | It renders as plain text (not a link) and a console warning is logged. |
| **Zoom at its limits** | Clamped to 0.5×–3×; further wheel input does nothing. |
| **Hover while dragging** | The highlight stays on the node being dragged until release. |
| **Browser resize** | The ellipse and ring are recomputed, nodes spring to their new slots, and the zoom level is kept. |
| **Reduced motion** (`prefers-reduced-motion`) | The ring stops, scrolling jumps instead of animating, and **nodes and topics snap** to their slots with no spring. |
| **DATA over the limits or malformed** | The template's `normalize()` is a safety net: it keeps the first 6 subfields and 5 topics, drops unknown `connects` ids, resources for unknown subfields and duplicate reference ids, and logs a warning for each. Agent E must not rely on it (see *Validation before write*). |

## Interaction Primitives

- **Click the dot / Enter or Space on a focused subfield:** expand or collapse its topics.
- **Click a name** (area or subfield): go to its Overview section (a real link, with history).
- **Drag a node:** move it; on release it springs back to its slot. A press counts as a drag only after the pointer moves 4px.
- **Hover or focus a node:** highlight it and its neighbors, and fade the rest.
- **Ctrl/Cmd + mouse wheel:** zoom from 0.5× to 3×, anchored on the center. **A plain wheel scrolls the page**, so the map never traps scrolling. Ctrl +/− still zooms the browser page.
- **No panning, and no adding connections:** you can rearrange the graph but not edit it.
- **Tab** moves through: the nav, the scroll cue, the root name, each subfield (as a button, then its name link), and then the text below.

## Accessibility Floor

- **Contrast:** text, text-body, muted, primary (7.4:1) and secondary (5.7:1) all pass AA on black. `edge-link` at rest is 3.1:1, which meets the 3:1 rule for graphics. `{colors.line}` is used only for decoration. Informative Orbitron is never below 10px.
- **Keyboard:** everything is reachable. Subfields are focusable buttons, names are real links, and focusing a citation's reference keeps your place. Every focusable element shows a `focus-outline`.
- **Motion:** `prefers-reduced-motion` stops the ring, smooth scroll and the springs.
- **Semantics:** the `top-bar` and index are labelled `<nav>` elements. The SVG is labelled with the area name and the ring is hidden from assistive technology. References are list items, and external links say "(new tab)".
- **Content parity:** everything on the map is also in the text. Topics are in the `topics-line`, connections in the `connects-line`, and the counts in the headings and meta lines.
- **Mouse-only:** only dragging and zoom.

## Responsive & Platform

Desktop browsers, roughly 1280px wide and up. Mobile and touch are out of scope. The map section is `100vh` with a `{spacing.map-min-height}` minimum, and its geometry scales with the viewport.

## Inspiration & Anti-patterns

- **Inspired by:** spacex.com and tesla.com (restraint, uppercase tracking, black canvas), the **Obsidian** graph view and **Quartz** (quartz.jzhao.xyz) (hover to highlight neighbors, draggable nodes, labels that appear with zoom), and the *Map of Mathematics* poster (`../map-of-mathematics.webp`: the area at the center with subfields around it, as a concept only).
- **Rejected along the way:** background guide circles, dotted lines, a rainbow or one color per subfield, a floating "Read overview" button on the map (it cluttered it), force-directed physics with nodes that drift or stay pinned where dropped, and panning the whole graph.

## Data Contract (Agent E)

Agent E writes one JSON document into `<script type="application/json" id="km-data">` in a copy of the template. Nothing else in the file changes.

**Serialization (mandatory):** build the object in memory, serialize it with a real JSON encoder (never hand-concatenated strings), then replace every `</` with `<\/` so the text can't close the script tag. Apostrophes, quotes and accents are then always safe.

```json
{
  "area": "Robotics",
  "generated": "YYYY-MM-DD",
  "intro": ["<html paragraph>", "..."],
  "subfields": [
    {
      "id": "kebab-id",
      "name": "Sub-field Name",
      "topics": ["Plain text topic", "..."],
      "overview": ["<html paragraph>", "..."],
      "connects": ["other-kebab-id", "..."]
    }
  ],
  "resources": {
    "kebab-id": [
      { "id": "author2020", "type": "BOOK", "citation": "<html ABNT citation>", "url": "https://... or empty" }
    ]
  }
}
```

| Field | Source | Format |
|---|---|---|
| `area` | `SUB_FIELDS.md` `## <AREA_NAME>` | plain text |
| `generated` | the run date | `YYYY-MM-DD` |
| `intro` | `OVERVIEW.md` area introduction | array of HTML paragraphs (inline `<b>`, `<i>` and `citation-link` only) |
| `subfields[].id` | slug of the name | lowercase ASCII, hyphen-separated, unique |
| `subfields[].name` | `SUB_FIELDS.md` `### <SUB_FIELD>` | plain text |
| `subfields[].topics` | the sub-field's bullets in `SUB_FIELDS.md` | plain text, 0–5 |
| `subfields[].overview` | the sub-field's section in `OVERVIEW.md` | array of HTML paragraphs |
| `subfields[].connects` | the sub-field's **connects to** list in `OVERVIEW.md` | ids of other sub-fields; one direction is enough |
| `resources.<id>[]` | `<SUB_FIELD>/RESOURCES.md` | `id` = first author's surname + year, lowercase ASCII (`cormen2022`, then `cormen2022b` if it repeats); `type` ∈ BOOK, PAPER, COURSE, ARTICLE, VIDEO; `citation` = ABNT NBR 6023 HTML with the title in `<b>`; `url` = DOI or URL, or `""` |

In-text citations inside `intro` and `overview` are written as `<a class="cite" href="#ref-<resource id>">(SURNAME, YEAR)</a>`, using ABNT in-text form.

**Validation before write.** Agent E checks every item; each line says what to do when it fails.
1. 1–6 sub-fields → if more, keep the first 6 in `SUB_FIELDS.md` order and report the rest to the orchestrator. If none, **fail** the run.
2. ≤ 5 topics per sub-field → truncate to the first 5.
3. Sub-field ids are unique slugs → re-slug any collision with a `-2` suffix.
4. Every `connects` id exists and isn't the sub-field itself → drop the bad ids.
5. Every key in `resources` is a sub-field id → re-key it by matching the sub-field name; drop it if there's no match.
6. Resource ids are unique across the page → add `b`, `c`… to duplicates and fix the citations that point to them.
7. Every `citation-link` `href` matches a resource id → fix it, or remove the link and keep the text.
8. `intro` and each `overview` are non-empty → if one is missing, use one paragraph from `SUB_FIELDS.md` and report the gap.
9. JSON is produced by an encoder, with `</` escaped → never write the JSON by hand.

**Upstream requirements:**
- **Agent D (`OVERVIEW.md`)** must end each sub-field section with a `connects to` list naming the other sub-fields it relates to. That list is the only source of map links. Its in-text citations must be in ABNT form and match ids in the resource lists.
- **Agent C (`RESOURCES.md`)** must give each entry a **type** and a **DOI/URL when one exists**, with citations in ABNT (NBR 6023).

## Key Flows

### Flow 1 — Getting oriented in Robotics (João, Saturday evening)

1. João sits down on a Saturday evening wanting to start learning **Robotics**. He opens his computer and invokes the skill with "robotics".
2. The agents run. When they finish, the page opens in his default browser on the **Map**: ROBOTICS sits in the center, its subfields are spread around it, and the telemetry ring turns slowly in the background.
3. He **looks around the map**: he hovers subfields to see which ones connect and clicks dots to fan out their topics, getting a sense of what the field is made of.
4. **Climax:** he clicks the name of a subfield that caught his eye and lands on its Overview section. Reading it, with its TOPICS and CONNECTS TO lines, the structure of the field clicks: how this part connects to the whole, and what he'll be studying. `[ASSUMPTION: the user didn't name the climax beat]`
5. He **reads the Overview**, using the sticky index to move between subfields.
6. He **reads the Resources**, sometimes by clicking a citation in the text and pressing Back to return. He opens the books and papers he wants to start with (`OPEN ↗`).
   - *Edge:* one subfield is too new to have academic sources. Its group shows `No sources found for this subfield.` and its meta line says `0 SOURCES`, so he knows that gap is in the research, not a bug.

### Flow 2 — Agent E renders a map (orchestrator hand-off)

1. The orchestrator starts Agent E once `SUB_FIELDS.md`, `OVERVIEW.md` and every `<SUB_FIELD>/RESOURCES.md` exist.
   - *Failure:* `SUB_FIELDS.md` is missing or has no sub-fields → stop and report; there is no page to make.
2. Agent E reads the three sources and builds the DATA object according to the field table.
   - *Failure:* a `RESOURCES.md` is missing → that sub-field gets an empty list (its "No sources found" state) and the gap is reported.
3. It runs **Validation before write** and fixes or drops what fails, as each rule says, keeping a list of every change.
4. It copies `assets/knowledge-map-template.html` to `./<area-slug>/MAP.html` and writes the JSON into `km-data`, encoded and `</`-escaped.
   - *Failure:* the JSON doesn't parse back → fix it and rewrite; never ship a page that fails to parse.
5. **Climax:** the orchestrator opens the file in the default browser, and the map appears with every node, link and count matching the sources.
6. Agent E returns a short report: the file path, the counts, and every validation fix or upstream gap.
